# 让 AI Passport 看电视直播

把 FoloToy AI Passport 变成一台网络电视机顶盒。设备上一共三个键，就能换台、调音量、调亮度、挑频道。

和官方固件一样，这台设备原样保留出厂身份信息，刷写不会动它。

## 开始之前，你需要

| 东西 | 说明 |
| --- | --- |
| **AI Passport 一台** | 硬件不变，只是换固件 |
| **一台电脑** | 平常的笔记本或台式机即可，Windows、macOS、Linux 都行。下面叫它"电脑" |
| **同一个 WiFi** | 设备和电脑连在同一个网络里 |
| **数据线** | 刷固件时把设备连到电脑上，刷完就可以拔 |

电脑要一直开着——它负责把网络上的电视信号转成设备看得懂的格式。关掉电脑，设备就停在等待画面上。电脑上不需要预先装什么，下一步的下载方式会自己把缺的东西补齐。

## 它是怎么工作的

设备本身的算力放不动视频，这件事绕不过去。所以真正的活由电脑干：电脑从网上拉一路电视信号，转成设备能直接显示的画面和声音，通过局域网送过去。设备只做两件事——把收到的图画出来，把收到的声音放出来。

这也解释了几个现象：

- **换台要等几秒**。每换一个台，电脑要重新开始转换。
- **电脑必须开着**。它是真正的信号源。
- **频道来自公开的网络直播源**，由电脑去取。这些源由社区维护，会失效，也会恢复。

## 第一步：刷固件

**推荐用网页直接刷**，不用装任何软件：

1. 用 **Chrome 或 Edge** 打开 <https://zpdeng1020-coder.github.io/ai-passport-tv/flash/>
2. 数据线连上设备
3. 点"连接设备并刷入"，在弹出的窗口里选中设备对应的串口
4. 写完后**按住电源键约 2 秒关机，再按住约 0.5 秒开机**

设备内置电池，拔线不会重启它。不做第 4 步，屏幕是黑的。

这个页面**只写入固件占用的那一段，不会擦除设备**，它会自己核对写入范围，越界就拒绝开始。

---

也可以手动刷，效果一样：

1. 到本仓库的 **Releases** 页面下载 **`FoloToy-AI-Passport-tv.bin`**。

   这个文件里包含引导程序、分区表和应用程序，从地址 `0` 开始一次写完，不需要你管偏移量。

2. 装一个刷写工具。用 Python 的话最省事：

   ```sh
   pip install esptool
   ```

3. 数据线连上设备，然后刷：

   ```sh
   esptool.py --chip esp32c3 --port <你的串口> write_flash 0x0 FoloToy-AI-Passport-tv.bin
   ```

   `<你的串口>` 在 macOS 上形如 `/dev/cu.usbmodem101`，Windows 上是 `COM3` 这样的名字，Linux 上是 `/dev/ttyUSB0`。插拔设备前后各列一次串口，多出来的那个就是它。

> **绝对不要用 `erase-flash`。** 设备里有一块出厂写入的身份信息，擦掉就找不回来了。上面这条命令从 `0` 写到约 `0x182000`（1.5 MB），而身份信息在 `0x356000`，中间留着距离——所以它是安全的。`erase-flash` 会把整块芯片清空，包括那块身份信息。

## 第二步：让电脑开始放电视

这一头要跑一个程序。它做两件事：从网上拉一路电视信号转成设备看得懂的格式，同时开一个网页让你挑频道。程序有两种拿法，任选一种，效果完全一样。

### 省事的做法：下载一个文件

到本仓库的 **Releases** 页面，按你的系统下载对应的那个：

| 你的电脑 | 下载这个 |
| --- | --- |
| **Windows** | `tv-server-windows-amd64.exe` |
| **Mac**（M 系列芯片） | `tv-server-macos-arm64.zip` |
| **Linux** | `tv-server-linux-x86_64.zip` |

Mac 和 Linux 下载的是压缩包，**解压后再运行**。压缩包是为了保住"可执行"这个标记——直接传程序文件的话，那个标记会在下载途中丢掉，双击会被系统拒绝。

> **Intel 芯片的 Mac 没有现成文件**，请用下面"从源码跑"那条路。构建机器只有 M 系列芯片的，造不出 Intel 版本——这一点宁可说清楚，也不要让你下载一个跑不起来的文件。

下载完放进一个空文件夹，双击。**电脑上不需要预先装任何东西**——程序第一次运行时会自己把缺的视频转换组件取回来（约 21–31 MB，只此一次，之后不再联网）。

第一次双击时，系统可能会拦一下，说文件来自身份不明的开发者。这不是文件坏了：这个项目没有购买代码签名证书，所以系统认不出它。绕过去的办法是——

- **Windows**：点"更多信息"，再点"仍要运行"
- **macOS**：右键点这个文件，选"打开"，再确认一次

只需要做一次，以后双击就行。

### 开发者做法：从源码跑

已经装了 Python 和 ffmpeg 的话，克隆仓库然后跑脚本：

```sh
./run.sh          # macOS / Linux
```

Windows 上双击 `run.bat`。缺什么它会告诉你，并给出你系统的安装命令。

### 起来之后

两种做法看到的画面是一样的：

```
数据目录：/Users/you/Downloads/ai-passport-tv
频道配置页：http://127.0.0.1:8097
  在这台电脑的浏览器里打开它，挑选频道、调整顺序。

正在监听 192.168.1.20:8096

设备配网页上要填的服务器地址：
    my-laptop.local:8096
```

**把 `my-laptop.local:8096` 这一行记下来**，下一步要填。它显示的是你这台电脑的名字，所以路由器换 IP 之后也不用改。

"数据目录"那一行指的是频道表存在哪。下载的那个文件放在哪里，数据就存在哪里；那个目录不可写时，程序会改用系统给每个用户留的位置，并把实际路径打印出来。

### 如果设备连不上，先看防火墙

**Windows 默认会挡住外面的设备来连。** 这台电脑上的浏览器能打开配置页，设备却连不上服务器，而且设备上只会显示"连不上服务器"，看不出是防火墙——这是最常见的一个坑。

放行办法：第一次双击运行后，Windows 一般会弹一个"是否允许此应用通过防火墙"，勾上**专用网络**就行。要是当时点了取消、或者根本没弹，手动加一条：

```powershell
# 管理员 PowerShell
New-NetFirewallRule -DisplayName "AI Passport TV" -Direction Inbound -Protocol TCP -LocalPort 8096 -Action Allow -Profile Private
```

macOS 和 Linux 通常不需要这一步。

## 第三步：把设备连上

设备第一次开机时自己会进配网模式，屏幕上显示彩条和一个网络名，形如 `FoloToy-XXXX`。

1. **用手机连那个网络**（没有密码）。手机可能提示"无互联网连接"，选仍然连接。
2. **打开浏览器访问 `192.168.4.1`**。
3. 填两样东西：
   - 你家的 **WiFi 名称和密码**
   - **服务器地址**：填上一步记下的那一行，例如 `my-laptop.local:8096`
4. 点连接。设备会自己重启，热点消失，几秒后画面出来。

如果没自动进配网，或者要改地址：**双击 ↑** 打开状态页，在状态页上 **长按 ↑**。

## 平时怎么用

三个键，六种手势：

| 操作 | 作用 |
| --- | --- |
| **短按 ↑ / ↓** | 换台 |
| **长按 ↑ / ↓** | 调音量，每次 10% |
| **短按 OK** | 打开频道列表（↑↓ 移动，OK 选中） |
| **长按 OK** | 调亮度 |
| **双击 ↑** | 打开状态页：当前频道、WiFi 信号、电量 |
| 状态页上**长按 ↑** | 重新配网 |

音量和亮度会记住，下次开机还是你调的值。

## 换频道

设备上的频道表是可以改的，不用重新刷固件。

启动服务时窗口里会打印一行"频道配置页"的地址，形如 `http://127.0.0.1:8097`。**在那台电脑的浏览器里打开它**，你会看到：

- 左边是从直播源里找到的频道
- 右边是设备上现在有的频道

添加、删除、调整顺序，然后点保存。服务会自动重启，设备重新连上，新的频道表就生效了。

页面上还有一个**"检测失效"**按钮。它会挨个试一遍，标出哪些频道已经播不出来。公开直播源会失效，隔一段时间点一次，把失效的剔掉即可。

频道表就是一个文本文件（`channels.txt`），直接编辑也有效，改完重启服务。两种方式等价。

## 出问题了

**设备屏幕显示"连不上服务器"**

电脑那头的服务没在跑，或者地址填错了。双击 ↑ → 长按 ↑ 回去重新填。地址建议填电脑的名字（形如 `my-laptop.local:8096`），不要填 IP。

**画面卡住，或者一直停在"正在连接"**

电脑上的服务窗口在的话，看它有没有报错。频道源本身会失效——用配置页的"检测失效"看一眼，换一个台试试。

**设备屏幕一直闪、台名快速跳变**

正在播放的频道失效了，设备在一个个往后试。等一下它会停下来，或者手动换个台。

**配网页面打不开**

手机连上 `FoloToy-XXXX` 之后，可能过一会儿自动切回了家里的 WiFi。把"自动加入"关掉，或者手动切回去。

**换台很慢**

正常。每换一个台，电脑都要重新开始拉流和转换。网络直播源尤其慢。

## 测到什么程度

说清楚哪些是实际跑过的，哪些不是，比笼统说"应该能用"有用。

**实际验证过的**

- **Windows 11 上完整跑通**：下载的 `.exe` 在一台没装 Python、没装 ffmpeg 的机器上启动，自动取回 ffmpeg，两个服务起来，127 个频道可用。用的是真机器，不是模拟。
- **macOS 上完整跑通**：构建、启动、取流、频道表保存后自动重启，逐项验证。
- 服务器的构建由 CI 在 Linux、macOS、Windows 三个平台上分别执行，每个平台构建完立刻启动一次做冒烟测试。

**没有验证的**

- **Linux 上没有人真的用过**。构建和测试都在 CI 里跑通了，但 CI 环境不是桌面环境，没有真人点过。
- **macOS 的 Intel 版本没有在 Intel 机器上跑过**，只在 CI 里构建。
- 苹果的系统可能会拦下未签名的程序，具体表现随系统版本和设置而变，只按常见情况写了上面那段。

**已知会遇到的**

- 公开的直播源会失效。这是常态，不是故障——用频道配置页的"检测失效"剔掉即可。
- 换台要等几秒，因为每换一个台电脑都要重新开始转换。

## 自己编译固件

需要 ESP-IDF 5.5.3。在仓库根目录：

```sh
./tools/validate.sh --prototype
```

这会构建、校验，并把成品写到 `build/FoloToy-AI-Passport-prototype-public.bin`——就是第一步要刷的那个完整镜像。

配置全部在设备的配网页上做，编译期不需要填任何东西。
